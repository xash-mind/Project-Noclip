## Dev.9.6 — Noclip Studio visual/material authoring

The current branch migrates safe Level 0 visual/material ownership into structured PAU/NAL authoring without moving world law into Studio.

### Structured source architecture

Studio authoring is generalized from the original Bucket/Can-only source into explicit Feature and Material sources:

```text
src/presentation/definitions/level0-features.json
src/presentation/definitions/level0-materials.json
```

Both are validated/generated by `scripts/build-presentation-definitions.mjs` and composed into the canonical project Presentation Registry.

### Structured Level 0 visual targets

Dev.9.6 makes these safe presentation targets structured-editable:

- M-W1 Level 0 Wallpaper;
- M-A1 Arch Pale Structural Finish;
- M-C1 Level 0 Carpet;
- M-CE1 Level 0 Ceiling;
- Level 0 casing/raceway appearance;
- Level 0 outlet appearance;
- M-F1 visible fluorescent-panel appearance only;
- CV-H1 visible depth/void materials only;
- existing Medium Bucket / Small Grey Open Paint Can PAU pilot controls remain supported.

World-owned geometry/generation values remain read-only.

### First-class Asset slots

Representations can now expose typed editable Asset slots declaring required Asset type/Profile/role. Studio may preview/save only compatible NAL Assets.

M-W1 owns canonical A/B/C Wall Texture slots rather than relying on hard-coded renderer Asset IDs.

Carpet and ceiling preserve truthful procedural source modes while optionally accepting compatible imported Floor/Ceiling Texture Assets.

### Non-destructive image treatment

Image-backed material use may apply brightness, contrast, saturation, pattern size and relevant tint/UV/rotation/flip controls without rewriting source image bytes.

The browser renderer uses a bounded derived-texture cache keyed by Asset content hash plus transformation signature; no per-frame Canvas processing is introduced.

### Ordinary sparse-pillar correction

Generation was not the stale-pillar defect.

Sparse Ordinary Level 0 pillars and Pillar Field pillars already originate from the same Generation 3 pillar system and carry `materialId: level-0-wallpaper`.

The old renderer path assigned the legacy procedural wallpaper to every column, then only replaced Pillar Field columns through the supplied A/B/C path. Dev.9.6 removes that artificial presentation split.

All eligible wallpaper-bearing columns now resolve through the same M-W1 inputs and deterministic A/B family decision as the rest of the wallpaper presentation.

### A-A1 ownership

A-A1 remains a non-wallpaper structural assembly.

- normal Arch Room walls -> M-W1;
- A-A1 semantic/reconstructed structural pieces -> M-A1;
- A-A1 topology, dimensions, openings and collision remain code/world-owned.

### Studio safety retained

Dev.9.6 preserves:

- loopback-only privileged Studio server;
- development-only game bridge;
- protected-branch/detached-HEAD write blocking;
- pre-existing dirty-file protection;
- explicit structured-source write allowlist;
- NAL import validation;
- hash-guarded targeted revert;
- whitelisted validation commands;
- no arbitrary shell/eval/source writer;
- no Studio commit/push/merge/deploy authority;
- production bundle boundary scan.
